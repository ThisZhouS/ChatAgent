# UI 工作流 / UI Workflow

## ChatAgent 专项交互

界面核心不是展示模型推理，而是展示委托关系和可恢复状态：AI 身份/负责人、任务目标、当前步骤、附件版本、等待输入/审批、产物、交付回执、失败原因、取消和对账入口。完整 reasoning_content 不广播给聊天成员。

发送、审批、取消、下载和转发按钮只表达状态，服务端仍必须认证和授权；审批确认页展示不可变内容摘要、收件人、附件 hash/版本和有效期。未知交付状态不能渲染为成功，模拟网关明确显示“模拟”。

为私聊、群聊、工作台任务详情分别设计空、加载、拒绝、断线、重试、已取消、等待审批和未知回执状态。验证中文长文本、文件名、表格、键盘焦点、SSE 断线补发和双用户对象隔离；截图不替代端到端流程证据。

用于 Web UI、Element/Element Plus 界面、前端重设计和浏览器可见交互变更。纯后端请求不应强制进行视觉重设计。

## 工作流 / Workflow

1. 从用户任务和系统行为开始。对每个交互能力说明触发方式、输入、校验、加载、成功、失败、空状态和恢复路径。
2. 在重要实现前创建或更新 UI 蓝本，包含信息层级、导航、交互模式、组件状态、响应式规则、可访问性要求和视觉主题，并放在项目设计或产品文档附近。
3. 复用现有组件库、设计 Token、图标和布局约定。没有现成约定时，选择适合领域的克制设计系统并记录决策。
4. 需要外部示例时，检查 `assets/` 中已下载的资源以及 [references/external-sources.md](references/external-sources.md) 中的来源目录。复制代码或模式前检查许可证、依赖兼容性、可访问性和可维护性。
5. 围绕行为和数据契约构建可复用组件，不要只围绕一张截图构建。控件必须覆盖键盘和焦点、禁用和加载、错误、校验和反馈状态。
6. 保持页面响应式且稳定。为网格、工具栏、磁贴和动态面板使用明确尺寸或布局约束，避免文字重叠、含义不清的图标按钮和干扰任务的装饰。
7. 在真实浏览器中使用代表性的桌面和移动端尺寸验证。检查视觉渲染、主要流程、网络失败、键盘和焦点行为、加载顺序以及浏览器控制台错误。
8. 在任务或验收记录中写明确切的启动、Lint、测试和浏览器验证命令。

## 完成标准 / Completion Criteria

- UI 蓝本与实际交互一致。
- 主要用户流程可以端到端运行。
- 已验证响应式布局和文字适配。
- 浏览器控制台没有项目导致的错误或未解释的警告。
- 外部资源和代码片段有来源记录且许可证兼容。
