# ChatAgent 工程约束

AI 是有明确 AI 标识、负责人、权限和生命周期的工作主体。交付标准是授权任务形成可验证产物与回执，不是回答“完成了”。独立账号不等于无限权限，也不等于第三方平台允许个人账号自动化。

## 每次实施

1. 读取仓库规则、当前代码、需求和本次 Prompt。复核 [基线审查](references/code-audit.md) 的符号；它是 2026-09-13 本机快照，不是永久 Bug 列表。
2. 区分内网原生聊天、外部 IM 适配与管理台；划定一个可验收切片：输入 → 身份/权限 → 任务 → 工具 → 产物 → 审批 → 交付 → 回执。写明修改范围和非目标。
3. 先定义失败、取消、重复请求和副作用语义。授权由服务端执行，不把判断交给提示词。
4. 按需读 [产品架构](references/product-architecture.md)、[实现契约](references/implementation-contracts.md)、[安全与办公](references/security-office.md)、[交互设计](references/ui-design.md)，不要一次加载全部。
5. 按 [开发阶段](references/delivery-plan.md) 推进，用 [验收矩阵](references/acceptance.md) 选回归。保持现有 TS/Fastify/Vue 边界，除非记录了迁移理由。
6. 交付变更、实际命令与结果、阻塞路径。Mock、接口集成、真实模型、真实 Hermes、真实收件人分别标记，不互相替代。

## 核心不变量

- completed 来自结构化结果和任务验收；异常、取消、步数耗尽、空响应不能经默认文本变成成功。
- 身份来自验证过的会话或网关；账号、会话、文件、任务、审批、事件流按组织与成员授权，同组织不同用户也隔离。
- 工具副作用统一执行：参数校验 → 当前权限 → 必要审批 → 幂等记录 → 执行 → 回执；模型、REST、Webhook、定时任务不能绕过。
- 审批绑定内容、附件版本和接收主体；内容、目标或权限改变后重新评估，不拿旧审批发送新内容。
- 产物创建时关联 taskId/runId/ownerId，不通过全局文件前后差集认领。
- 重启保留待办、审批、事件和副作用结果；重试可安全恢复步骤，不重放整个已外发任务。
- 文件、聊天和检索内容是不受信任数据，不能扩大工具权限或读取服务器秘密。

## 开发与运行时

DeepSeek Harness 是开发工具；Hermes 是产品拟采用的运行时，包名不能证明集成。使用 DeepSeek 时另读相邻 deepseek-harness-workflow 技能；不可用则报告缺口，不伪造命令。

本技能不会自动安装依赖、调用付费模型、外发消息、改全局配置或授权子代理。仅升级 skills 时，不顺便重写业务代码。
