# ChatAgent 完整产品理念与可应用性审查

审查日期：2026-09-17。代码基线：`c851228`。审查开始时工作区无业务改动。

本次按“解决什么问题、员工能完成什么工作”审查，而非只核对 Host 加固清单。证据包括当前源码、现有文档及本轮自动化测试；未使用真实模型凭据，未运行真实 Hermes 办公、安装包 GUI 或双机人工验收。历史记录不作为本轮实测结果。

## 1. 产品应当解决的问题

ChatAgent 是“自带员工聊天系统的 AI 工作助手”，不是第三方 IM 的机器人接入平台，也不是给聊天界面附加一个模型 API。

应交付四种可用能力：

1. **员工协作**：员工在自己的内网系统中找同事、单聊、群聊、共享文件、查找记录，无须 QQ、微信、飞书、钉钉。
2. **工作委托**：员工把目标与材料交给有身份、权限和责任边界的 AI；AI 完成处理并交付文件，而非只回答操作步骤。
3. **同机并行**：员工正常使用电脑和聊天时，Hermes 在后台处理任务，不抢输入、不改坏正在编辑的原文件。
4. **独立与无人操作运行**：无组织服务器时仍可使用本机 Agent；员工暂时离开时，已授权任务可继续，预设任务可按规则触发。

生命周期遵守 ADR-0003：**关闭窗口→托盘常驻继续；明确退出→停止 Host/Hermes 并回收自有执行进程**。不新增守护进程或 Windows Service，不要求退出、关机、睡眠后仍持续执行。无人操作不意味着无人审批；独立本机模式不等于模型一定离线，需要分别说明。

## 2. 总体判断

**已经具备有实质功能的原生聊天应用，以及逐步完善的桌面后台执行基础；但尚未把它们连成统一、真实、可日常使用的工作助手。**

主要断点是：聊天交办走服务端 TypeScript 执行链，本机 Hermes 走另一个任务入口，回执同步不提供任务下发、附件传递或产物交付。不能将“接通真实模型”视为唯一剩余产品工作。

不宜给完成度百分比：聊天、Host 可靠性与办公任务闭环的分母不同。更准确的阶段是：**原生聊天与后台执行底座的集成开发阶段，尚待以真实业务闭环取得助手试用资格**。

## 4. 核心产品缺口

### GAP-01 / P0：聊天交办与本机执行没有统一闭环

证据：`apps/server/src/app.ts:208` 创建本地 TS 包的 `HermesAgentRuntime`；`apps/server/src/service.ts:2243` 的任务调用该运行时。`apps/desktop/main.cjs:572` 另建 `LocalAgentHost` 与 `HermesProcessAdapter`。`apps/server/src/app.ts:974` 明确说明 `/api/local-tasks` 是设备回执镜像，没有服务端到设备的命令路径。本机任务由设置页或本机工作台另行提交。

影响：不能据回执功能宣称“员工在聊天中交文件，自己的电脑在后台处理，结果回到同一会话”。服务端已有文档回传，但不能替代本机路径。

方向：复用服务端执行器，建立统一工作契约和执行位置选择，关联 `taskId/accountId/requesterId/deviceId/conversationId`。由受信主进程领取指定设备、指定权限的任务；离线时明确等待或由用户选择其他执行位置，不悄悄降级为 fake。下发受限工作协议，不开放远程命令行。

### GAP-02 / P0：本机文件输入、结果取用和组织交付断开

证据：`packages/agent-host/src/ipc.ts:18` 开始的命令面有提交、查询、取消、重试，但提交参数没有输入附件契约；`apps/desktop/workbench.html:115` 是目标文本入口，`:204` 只显示产物名称；`apps/desktop/preload.cjs:1` 的桥面没有文件选择、受控打开或导出接口。

影响：缺少“选材料→允许读取→查看实际结果→打开/另存→发回会话”的正常操作链。不能要求员工手工找工作目录，也不能把回执名称/hash 当成可下载文件。

方向：增加选择/拖入和聊天附件受控下载，用文件 ID、版本/hash、用途与权限建立输入清单；默认复制进任务工作区，不覆盖原件。结果提供预览、打开、另存、上传和发送。组织上传取得受控文件 ID 后再附到消息；独立模式可本地导出，不强制组织登录。

### GAP-03 / P0：真实 Hermes 的接入不只是模型凭据

证据：`apps/desktop/main.cjs:213` 查找环境变量指定、资源目录或开发 Temp 目录的运行时；`:576` 创建适配器时未显式传入模型/提供商，缺运行时则使用 FakeHermesAdapter。`apps/desktop/package.json:1` 的打包清单未配置 Hermes 运行时资源。

`packages/agent-host/src/adapter.ts:66` 将 `document`、`messages.send` 都映射到 Hermes `file` 工具集。服务端 Word/Excel 与消息工具不会因名称相同自动成为真实 Hermes 的工具。

影响：进程启动、能写 `result.md`，不证明会合并 Excel、编辑 Word、把附件发给同事；接通模型也不会自动补齐工具。

方向：提供运行时安装/检测、模型连通验证与能力探测；接入受控办公和消息工具，保留执行器来源标识。生产不把 fake 成功算真实完成；组织发送经应用授权与投递通道。不要直接开放全部 terminal/browser/computer_use 来掩盖工具缺口。

真实验收记录应包含执行器、模型配置的非敏感标识、输入 hash、实际调用、输出、校验和交付对象，不记录密钥。

### GAP-04 / P0：Office 工具还不足以支撑可信日常办公

证据：`packages/document/src/limits.ts:18` 限制预览为 10 行；`packages/document/src/excel.ts:64` 生成预览，解析结果为行列数和预览；`packages/document/src/tools.ts:71` 返回该摘要。现有工具主要是解析和新建 Word/Excel，不能由此推导出全表查询/计算或原文件保真修改能力。

影响：模型基于前 10 行推断 5000 行的合计、去重或异常，会产生业务错误。限制预览本身合理，缺的是另一路全量、受限、确定性处理，而不是把全部数据塞进上下文。

方向：先做整表读取/分批查询、按列筛选、合并去重、分组汇总、类型与日期校验；由代码计算，模型组织步骤和解释。明确公式、格式、图表、宏支持边界；不支持保真编辑则拒绝或另存简化版，不能静默损坏。Word 先做模板填充、表格/章节修改、来源与版本输出，再扩展排版。

验收用合成数据，关键记录放在第 11 行之后，并含重复行、空值、中文、日期和公式；核对全量结果，不仅检查文件存在。

### GAP-05 / P0：员工没有完整的“授权我的助手”流程

证据：Host 已有可信授权注册表和持续复核；但 `apps/server/src/service.ts:1501` 只支持 `approval` 复核，`docs/tasks.md:239` 仍列委托台账/签发路径为未开始。`apps/web/src/views/AccountsView.vue:6` 保留 memory/第三方渠道式创建入口，未形成助手归属、设备绑定和委托设置流程。

影响：有校验不等于员工能授予权限；“批准一次发文件”与“允许什么时间、读取什么文件、向谁代办”不是同一种授权。

方向：建立员工→AI账号→设备→能力/目录/收件人/有效期的委托，提供创建、查看、撤销和到期操作；具体动作另走审批。消息显示 AI 执行者和委托人，不冒充员工。单机文件授权由本地可信确认完成，不能依赖不存在的组织服务器。

### GAP-06 / P1：后台可运行，不等于助手可持续自主工作

证据：`packages/agent-host/src/types.ts:16` 的本机状态主要为排队、运行、成功、失败、取消、中断；IPC 无补充材料/回答澄清命令。服务端虽有等待审批/输入及恢复机制，但不能算作本机 Hermes 已支持。适配器禁用 Hermes cronjob；未发现面向员工的定时/业务事件触发配置闭环。

影响：可继续一个已提交任务，但尚不能完整表达“每天 17 点整理材料”“缺字段时问我，回答后继续”“批准后只发送一次”。

方向：先做一个定时模板和一个附件到达事件，配置触发条件、时段、预算、过期/补跑与幂等；调度仍由常驻客户端管理。退出期间不执行，重开后按明确授权处理补跑，不偷偷重放外发。将待澄清、待审批、材料补齐、继续与交付确认整合为同一任务卡。

### GAP-07 / P1：员工使用路径与同机不干扰仍需补齐

现有本机任务入口在设置页或独立工作台，配置与诊断偏开发工具。应让员工清楚“我的助手在哪、读了什么、还需要我做什么、结果在哪”。

方向：首次运行区分个人本机使用/加入组织，引导运行时、模型自检、工作目录和助手设置。日常入口为聊天、我的助手和任务卡，设置页不承担主要业务流程。配置和诊断不得泄露密钥。

同机并行须实测：员工聊天/编辑时不抢焦点与键鼠、不锁原件；限制并发、资源和执行时长，显示进度及暂停/取消；源文件变化需冲突检测，默认另存。`windowsHide: true` 不能单独证明“不干扰”。

### GAP-08 / 发布门槛：工程通过不等于企业可交付

保留已有权限隔离、原生投递、持久化、回执、审批和桌面加固，不重造基础设施。仍需真实部署验收：干净 Windows 安装、局域网两机通信、地址配置、成员入职/停用、升级/回滚、备份与实际恢复、磁盘满/断网/重启、日志支持与容量。

明确数据边界：内网聊天不自动意味着模型处理不出内网。使用外部模型时说明传输内容和允许策略，组织可选择合适的模型部署方式。本轮未核实外部运行时的最新支持周期，正式发布前应依据官方资料确认，不沿用历史调研中的日期作当前结论。

## 6. 下一阶段交付顺序

### M1：本机真实办公助手最小闭环

两份合成 Excel → 本地授权 → 真实 Hermes 调受控工具全量合并去重/汇总 → 生成 Excel 和 Word → UI 打开/另存、查看来源与错误。

通过标准：无组织服务器、不是 fake、结果与确定性校验相符、普通员工从 UI 完成；关窗继续，明确退出停止，重开显示真实中断状态。先取得独立使用价值，不再单独累积与交付脱节的 Host 检查。

### M2：同一闭环接入原生聊天

员工 A 在 AI 会话上传材料 → 交办到 A 的已授权设备 → Hermes 后台处理 → 同一任务卡显示进度/追问/审批 → 文件回原会话 → 批准后发送给员工 B。

通过标准：身份/任务可追踪、附件不越权、实际产物可下载、B 收到受控文件而非本机路径、重试不重复发送、离线不冒充成功。复用已有审批和原生发送，不平行新造消息系统。

### M3：授权自主工作与员工并行

加入一个重复模板、定时/事件、待输入续办、委托撤销、源文件冲突与预算限制。验收锁屏、断网、关窗、暂停、明确退出和重开边界。

通过标准：无人操作时只在已有授权内工作；缺权限/材料停在可解释状态；重开后清楚已完成、待办和待确认输出。

### M4：小范围组织试用与正式交付

选择办公岗位和固定任务集，非开发者从安装开始操作；跨两机验收协作、恢复和运维。记录成功率、人工介入、耗时、重复发送和文件错误，不以单元测试数替代业务质量。

正式使用门槛：流程可重复、异常可恢复、管理员可维护、配置可复制、数据边界清楚。语音视频、移动端、第三方 IM、大型知识库和复杂多 Agent 编排不是本轮前置条件。
