# ADR-0002：员工聊天客户端与本机 Hermes 后台工作节点

2026-09-15 部分取代：用户要求后台与关窗常驻绑定，最新生命周期以 `adr-0003-window-resident-agent.md` 为准。下文独立于 Electron 主进程存活、额外服务化的建议不再是实施要求；双用途、受限并行和单机工作台目标仍保留。

日期：2026-09-14。状态：产品要求已明确；以下架构为实施建议，尚未实现或验收。

## 用户要求与对原路线的修正

同一台电脑、同一个 ChatAgent 产品，既可作为员工日常聊天工具，也可单独作为 Agent 工具。员工使用电脑时 Hermes 能在后台执行任务；没有员工操作时 Hermes 也能持续处理被授权的任务。

这不是互斥的“聊天模式/AI 模式”，也不是只有检测到空闲才启动 Agent。前台交互和后台执行必须具有独立生命周期。主流聊天工具仍不是依赖；ChatAgent 原生组织服务属于自己的协作系统，不等于依赖第三方 IM。

此前路线聚焦原生聊天可靠性，但未充分覆盖“本机 Agent 运行宿主”。增加 Gate 7A 的双模式最小验证，再推进原生持久化/同步和步骤续跑。生产可靠性门槛不因 PoC 优先而免除。

此次用户明确将后台 Agent 指为 Hermes，后续应验证真实上游运行时，不再仅以本地同名 TS 包代替。历史 Prompt 的“借鉴框架思路”记录保留，但不能满足这次新增的真实后台运行验收。

## 当前代码缺口

- `apps/desktop/main.cjs` 只加载服务端 URL；Windows 上 window-all-closed 会 app.quit。没有本地任务宿主、Hermes 进程管理或设备注册。
- `apps/desktop/preload.cjs` 只暴露只读元信息，应保留这条安全边界；不直接给聊天网页开放 shell、启动任意进程或读任意文件。
- `apps/desktop/package.json` 的打包文件为 main/preload/error/config，未包含本地应用服务或 Hermes 运行环境。安装 exe 不等于单机 Agent 可独立工作。
- `apps/server` 仍装配本地 TS HermesAgentRuntime。现有服务器任务能力可以复用，但不等于员工电脑上有独立 Hermes 节点。

## 建议结构

```text
员工电脑
  ChatAgent UI（Electron / 本地受信前端）
    ├─ 员工：联系人、聊天、群聊、文件
    └─ 助手：任务、计划、审批、权限、运行状态
               │ 经过认证的窄接口
  Local Agent Host（独立生命周期）
    ├─ 本地身份/配置/任务存储/检查点/事件记录
    ├─ 唯一调度入口、预算、启动/暂停/取消/恢复
    ├─ Hermes Adapter → 固定版本的真实 Hermes 执行进程
    └─ 受限工具 → 授权文件、独立工作目录、API、独立浏览器配置
               │ 设备凭据 + 委托权限 + 可恢复同步
  可选连接：ChatAgent 自有内网组织服务
    └─ 组织成员、聊天、群聊、审批策略、任务派发、回执与审计
```

以上模块名称是设计边界，不要求立刻创建这些包或拆成微服务。可从现有 Fastify/TaskEngine/文档服务中提取最小接口，但不要直接启动一个带全组织权限的生产 server 当成本地个人 Agent。

### 使用形态

| 形态 | 行为要求 |
| --- | --- |
| 单机 Agent 工具 | 不连接组织聊天服务器也能提交本地任务、查看产物和管理授权；模型仍需可用端点，不承诺天然完全离线 |
| 员工协作 + 后台 Agent | UI 正常聊天；Hermes 同时执行文件/API任务；两者互不阻塞，资源预算保障员工交互 |
| 无人操作/关闭界面 | 已启用后台运行时，不需要 UI 保持打开，已授权任务及计划继续；下次打开可查结果 |
| 专用 Agent 节点（后续） | 没有员工交互界面时也能在明确服务身份下执行委托；同一任务不可同时被本地与服务端执行 |

人类在线状态、设备在线状态、Agent 运行状态分开显示。员工离线不自动意味着 Agent 离线；电脑离线不允许服务器假称本地任务仍在执行。

## 不抢占员工操作

后台文件/API工具为默认路径：使用授权输入快照和任务工作目录，生成新版本后再交付；不在员工正在编辑的 Word/Excel 原文件上直接写入。使用文件版本校验/锁冲突策略，不无条件覆盖。

浏览器自动化默认使用独立 profile/进程，不复用员工私人登录会话；不得把独立 profile 当成充分的操作系统安全隔离。与用户桌面交互的 GUI 工具单独标为 requiresInteractiveDesktop：必须明确授权并具备抢占/让出机制，员工正在使用时不后台抢鼠标、键盘、剪贴板、焦点或共享屏幕。

执行并发、CPU/内存、模型请求数、token/费用和运行时长设可配置预算。初版先设置保守并发并测量 UI 响应，不用“低优先级进程”一句话承诺互不影响。

## 生命周期与 Windows 边界

初版承诺应限于“用户已登录，电脑开机且处于可执行状态”：

- 关闭窗口：按明确设置隐藏到托盘或退出 UI，Host 继续；首次启用需用户知情。
- 暂停 Agent：停止领取新任务，运行中任务按工具能力暂停/检查点/取消；不可撤销的操作不谎报已撤销。
- 退出 UI：不是停止 Agent；菜单分别显示“关闭界面”“暂停后台”“停止后台并退出”。
- 注销 ChatAgent：清理 UI 会话。后台只能按独立明确委托续跑；不得复制长期人类登录令牌维持任意访问。撤销 Agent 委托则停止新副作用。
- 锁屏/无人输入：受限无界面任务继续，GUI任务等待适当会话；不自动扩大权限。
- 操作系统注销或开机未登录：作为独立的服务化验收阶段；用户会话内进程和系统服务不能混为一谈。
- 睡眠/休眠/关机：不承诺本机任务持续执行。恢复后按策略补跑/跳过/合并错过任务；确需全天执行可使用单独的常开组织节点，需显式迁移权限和输入，不能静默上传本地文件。

托盘常驻只能说明 UI 进程未退出，不能证明 UI 崩溃后 Host 存活，更不能证明未登录时仍能执行。Host 要有独立启动、状态、停止和升级流程，不把不受监管的 detached 子进程当最终方案。安装后台服务、自启动或防休眠均需明确授权；服务身份遵循最小权限，不默认 LocalSystem。

Windows 服务与员工桌面有会话隔离；无登录时的服务不应依赖弹窗、可见浏览器或 Word GUI 交互。需 GUI 时使用经过单独授权的用户会话执行端，不尝试绕过锁屏。

## 身份、授权与本地通信

区分 humanId、agentId、deviceId、taskId、runId；一个身份可以有多设备，但任务派发必须有唯一执行者/租约，不能所有在线设备各跑一次。

组织服务向设备派发签名/认证后的有限任务，不向客户端开放任意远程 shell。设备只获得本次任务所需资源与有效期，离线权限缓存有到期策略；无法确认权限时暂停组织副作用，个人明确授权的本地工作可按本地策略处理。

本地 RPC/IPC 使用操作系统 ACL 或经配对的令牌、调用方/来源验证、窄 schema 和审计。监听回环地址不等于已经安全，远程聊天 HTML 不能调用任意本机工具。网络中的聊天/附件和模型输出都不是授权来源。

待审批时暂停相应步骤，不因“员工不在”默认批准，也不能让 Agent 自己替负责人审批。日常自动动作可以使用事先配置、可撤销、范围明确的授权策略，不必每次人工点确认。

## Hermes 集成规则

选定上游 commit/tag，核实许可证、目标 Windows 环境、启动/停止、工具注册、产物/事件、取消、会话与文件范围；外部研究文档只作为候选证据，安装版本必须本地验证。

保留当前 TaskEngine 作为 ChatAgent 的业务任务账本，通过 Adapter 调用 Hermes；不要同时保留两个相互不知道的调度器。初版由 ChatAgent/Host 统一创建任务并调用 Hermes；若以后采用 Hermes cron，需定义唯一调度所有者和 job→task 映射，再启用。

不能让 Hermes 的默认 shell/文件工具绕过 ChatAgent 工具策略；通过可验证的工具配置和执行环境限制能力。设置工作目录只限定默认位置，不等于文件访问沙箱。必须有拒绝访问工作范围外文件的测试。

## 下一步：Gate 7A 最小验证

先只验证一台 Windows 电脑上“真实 Hermes 与员工客户端并行且互不依赖 UI 生命周期”：

1. 一个单机本地任务入口，即使没有组织服务器也可管理授权目录、提交任务和查看结果；真实模型调用使用另行获准的合成文件。
2. 固定版本 Hermes 完成一个文档任务；进程版本、工具执行记录和可读产物证明不是 Mock 或同名 TS 循环。
3. 执行期间员工可持续聊天/操作 UI；任务不用员工鼠标键盘，输出不覆盖员工编辑的原文件。
4. 关闭窗口、重新打开，任务状态和结果仍在；单独终止 UI 测试进程不误杀 Host，Host 异常后任务不误标完成。
5. 在已登录但无人操作的测试场景触发一个授权计划任务；暂停/撤权有效，待审批不会自动发送。
6. 断开组织服务后授权本地任务仍按策略执行，依赖组织的动作排队或阻塞；重连不重复提交。

Gate 7A 不安装系统服务、不承诺注销后运行、不做 GUI 自动化、不全量拆包、不把测试文件发给真实成员。先写方案与隔离环境验收，再请求所需安装/模型调用授权。

## 后续顺序

Gate 7A：Host/Hermes 双模式 PoC → Gate 7：持久任务/原生消息/设备同步 → Gate 8：步骤检查点与审批续跑 → Gate 9：明确授权的计划/事件触发与服务化 → Gate 10：安装升级、设备治理、多人试点。
