# ChatAgent 需求 / Requirements

> 以验收信号为优先级排序；F=功能、Q=质量、C=约束。每条的**证据**指向仓库里可重复执行的用例或文档，
> 而不是「已经做过」的叙述。本文 2026-09-22 按已交付产品重建（旧版仍按 IM 平台/Webhook 为中心，
> 与 `docs/product-decomposition-gap-matrix-2026-09-17.md` 的方向漂移，见该文档 §5）。

## R1 身份、会话与成员（F/C）

- R1.1 成员凭据为「成员 ID + 令牌」，令牌只存 sha256；登录换取会话令牌（HttpOnly Cookie + Bearer），
  可列出并撤销自己的会话、可自助轮换令牌（旧令牌与全部会话立即失效）。
- R1.2 生产档位拒绝无凭据请求；`development` 档位的回环开发主体注入必须显式开启，**认不出的凭据是拒绝而不是忽略**。
- R1.3 成员、会话、文件、任务、审批、事件流都按组织与成员授权；同组织不同用户之间也隔离。
- R1.4 每个成员有一个**可搜索的唯一个人 ID（handle）**：组织内唯一、保留词拒绝、改名冷却、旧名保留期、
  老成员惰性分配。证据：`handles.test.ts`、差距矩阵 §3.21。

## R2 原生聊天与可见性（F）

- R2.1 会话模型：direct/group、text/file/image/mixed、mentions、附件、引用、转发溯源、撤回（窗口内）。
- R2.2 消息幂等：同一 `clientMsgId` 重放不产生第二条；事件流带 `seq`，重连按游标逐条重新鉴权回放，游标过期发 `resync`。
- R2.3 可见性在**发现层**：联系人列表只含与自己有关系的人（好友/待处理申请/备注或拉黑对象）+ AI 账号；
  全组织仍可通过目录搜索找到并添加；**在线状态只对本人与好友可见**（联系人、目录与 `/api/presence` 三处一致）。
  证据：`contact-visibility.test.ts`、`friends.test.ts`。
- R2.4 沟通层不受友谊限制：与未加好友的同事照常单聊、拉群、@ 与收发消息（回归用例钉死）。
- R2.5 群治理：群主/管理员改名、公告、加人、移出、解散；加人即授予历史读取权并写审计。
- R2.6 呈现：会话外观（闭集）、每查看者私有的会话/成员别名、免打扰（@ 例外）、表情与贴纸（闭集 id）。

## R3 AI 账号与分级（F）

- R3.1 AI 账号有独立身份、显示名、人设、状态与所属组织；令牌只返回一次、只存哈希。
- R3.2 人际好友管可见性、**AI 分级管能力**：`owner/confirm/chat/ignore` 四档，三处硬门
  （入站闸门、运行时 `allowedTools`、`POST /api/tasks` 403）。证据：`contact-tier.test.ts`、`runtime-allowlist.test.ts`。
- R3.3 工具能力唯一来源是宿主策略表（含能力下限）；提交期即拒绝被关闭或不存在的能力，
  拒绝原因回灌提示词，提示词只声明规则、不承担边界。

## R4 投喂闸门与任务（F/Q）

- R4.1 消息默认在撤回窗口结束后才交给 AI；窗口内撤回即取消投喂，且**取消发生在落库前**。
- R4.2 入队项有重试预算（默认 8 次、约 10 分钟退避），用尽即终态 `failed`；等待窗口不消耗预算；
  `/api/agent/status` 报 `pending/submitted/cancelled/failed/stalled`，会话只收到闭集原因码。
- R4.3 任务状态机 pending/running/waiting_input/waiting_approval/completed/failed/cancelled/incomplete；
  重启保留待办、审批、事件与副作用结果；重试可安全恢复步骤，不重放已外发任务。
- R4.4 澄清提问闭环：AI 反问 → 任务停在 `waiting_input` → 请求者的下一条消息续跑同一任务（他人消息不算答案）。
- R4.5 模型历史由服务端重建并按**请求者自己的偏好**取窗口（默认 20、1–200）；澄清追加同理（默认 50）。
  证据：`preferences.test.ts`、`agent-intake.test.ts`、差距矩阵 §3.19。

## R5 审批、副作用与交付（F/C）

- R5.1 有副作用的工具统一：参数校验 → 当前权限 → 必要审批 → 幂等记录 → 执行 → 回执；模型、REST、Webhook、定时任务都绕不过。
- R5.2 审批绑定内容、附件版本与接收主体（摘要），单次使用、可过期；内容或目标改变后必须重新评估。
- R5.3 投递按通道记录 outbox（`simulated` 不计为送达）；`unknown`（超时/5xx）需人工对账，不自动重发。

## R6 文件与文档（F）

- R6.1 上传按**文件签名与扩展名一致**校验（fail-closed，415 + 审计），失败发生在落盘前。
- R6.2 解析 .docx / .xlsx / .xls / .csv；生成 Word 与 Excel；能力以工具形式暴露给 AI。
- R6.3 产物创建时关联 taskId/runId/ownerId，不做全局文件前后差集认领；下载按会话参与者授权。

## R7 本机 Agent 宿主（Gate 7A，F/C）

- R7.1 本机宿主由 Electron 主进程管理（ADR-0003）：关窗托盘常驻，明确退出即停止 Host/Hermes 并清理自有子进程。
- R7.2 授权只走受信路径（委托/审批由主进程登记），本机不自我审批；副作用任务权默认 fail-closed，
  执行前复核授权，`unverified` 时暂缓而不失败。
- R7.3 工作目录硬约束 + 管理员预置允许目录白名单（默认空 = 旧行为），授权根先 realpath、空白条目跳过。
- R7.4 单写者锁：任务库由存活 pid 独占；歧义（pid 复用/锁损坏）时弹窗询问且默认不接管，接管写审计。
- R7.5 回执同步在主进程，按任务版本去重、失败分级（4xx 停止自动重试 / 5xx 与网络退避）；服务端拒绝 owner 不符的回执。

## R8 工作台与管理（F/Q）

- R8.1 侧边导航：聊天、工作台、任务、审批、文件、AI 账号、成员、设置。
- R8.2 管理台（组织所有者/管理员）：成员 CRUD、令牌轮换（只显示一次）、审计查询。
- R8.3 设置页含：我的登录会话、我的个人 ID、我的助手偏好、接入真实模型、审计日志；桌面壳另含本机 Agent 卡片。
- R8.4 关键流程有加载/空态/错误/成功反馈；键盘可聚焦；真实客户端检查含无错误提示、无横向溢出、无文字截断、亮暗主题对比度 ≥4.5、1024×720 布局。

## R9 质量与运维（Q/C）

- R9.1 一条命令可复现：`tsc --noEmit`、根套件 `vitest run`、`apps/web` 套件与 `vue-tsc`、Electron 七项、打包后 E2E、`scripts/live-boundary-check.mjs`。
- R9.2 退出码约定：**0 = 已验证 / 1 = 有失败 / 2 = 有未验证项**；任何验收脚本不得把「没跑到」说成「通过」。
- R9.3 配置走环境变量并在 `.env.example` 说明；不提交密钥；审计日志只写不删、不含令牌与消息正文。
- R9.4 无外部模型依赖时全链路可运行（MockProvider）；有真实凭据时只改环境变量即可切换。

## 非功能验收信号

- 员工从「发消息或丢文件」到「拿到产物与回执」的闭环可在本地完成，且**同一件事在真实客户端上被端到端跑过**（38/38）。
- 安全不变量（身份、对象授权、审批绑定、文件边界、工作目录）在**拒绝路径**上也有用例与运行态证据。
- 尚未验收：真实 Hermes + 真实模型凭据的办公闭环（Gate 7A.3）、双机局域网、安装包 GUI 人工验收、Electron 版本切换（需 registry 网络）、Windows Job Object 子进程回收、完整 XSS 利用链。
