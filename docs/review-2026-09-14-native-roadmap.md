## 结论与本次范围

ChatAgent 已从早期 Webhook/模拟管理台发展为有原生聊天和 AI 执行能力的独立应用原型。下一步不是重做认证、群聊或接入第三方平台，而是把已实现的原生流程变成可靠、可恢复、可用真实模型验收的工作系统。

用户明确：项目不依赖 QQ、微信、飞书、钉钉等聊天工具。以此为当前产品约束；无需第三方聊天账号、凭据、SDK 或消息服务即可完成安装、登录、聊天、文件、AI 委托、审批和内部交付。已有外部适配器可以继续默认禁用，不需要为证明独立而立即删除兼容代码，更不能把它们列为发布门槛。

本次只审查、运行现有测试/类型检查、更新方向文档，不修改业务实现、不启动/重启现有服务、不调用付费模型或真实收件人。

## 当前最重要的五个缺口

### NATIVE-01：收到成功回执不等于可靠持久化

证据：`apps/server/src/stores.ts:41` 的 JsonFileWriter 默认延迟 150ms，MessageStore/ConversationStore 使用 schedule；`native-gateway.ts:166` 调用 append 后在第 187 行返回 delivered。审批/outbox 与消息又位于不同 JSON 文件。

判断：内存/进程内入箱已经存在，但突然终止进程时可能出现“回执保存而消息未落盘”，或消息/会话/outbox 不一致。这是代码路径推导的风险，本轮没有杀进程复现，不能写成已确认数据丢失事故。

下一步：定义 accepted、持久入箱、客户端同步、已读的不同含义。重要成功确认必须在持久提交之后；消息、会话索引、投递回执、事件记录需要一致事务边界。优先为单实例设计事务存储接口与迁移 PoC，可评估 SQLite，不直接把 PostgreSQL/Redis/多实例变成前置条件。旧 JSON 迁移需备份、计数/归属核验和回滚，不丢历史数据。

### NATIVE-02：重连不等于补齐断线期间的数据

证据：`apps/server/src/events.ts:21` 为进程内事件分发；`apps/server/src/app.ts:1229` 的原生 SSE 订阅未见持久游标回放；`apps/web/src/views/ChatView.vue:634` 的 onopen 只改变连接状态，没有重连时的完整补齐流程。

下一步：持久事件序号、客户端游标、去重、补发和游标过期后的快照同步。断线期间的消息、撤回、群成员变化、任务和审批状态都必须补齐；每次补发用当前权限过滤，退群/撤权不能通过旧游标取回数据。自动重连、心跳和断线提示已经有，不要重复当成新功能。

### AGENT-01：任务“重跑”还不是步骤级“续跑”

证据：`packages/task-engine/src/engine.ts:159` 的 resume 重新排队；`apps/server/src/service.ts:2191` 每次 runTask 创建新 runId 并从 goal/history 调用 runtime。现有幂等以任务和 action digest 为依据，不能保证重跑模型生成相同文件 ID 或相同载荷。

风险推导：生成 Excel → 请求转发审批 → 批准 → 重跑模型，可能再次生成文件并要求新审批；长任务重启也可能重做已完成步骤。现有同载荷 outbox 去重有效，不应误称完全没有幂等；缺的是持久计划、步骤状态、工具结果和明确恢复点。

下一步：增加最小 TaskStep/Checkpoint，复用已生成 artifact ID/version 和批准载荷，从等待的步骤继续。原生入箱是本系统可控操作，优先用事务与唯一业务键保证一致，不要求另接外部网关。

### AGENT-02：真实工作能力需要独立于 Mock 的验收

证据：`apps/server/src/agent.ts:21` 缺模型配置仍返回 MockProvider，未按生产模式拒绝；`packages/hermes/src/providers/openai-compatible.ts:46` 仍是简单请求实现；`service.ts:2097` 把全部未撤回会话历史送入上下文，未见预算裁剪。

下一步：显式 demo/test/real 模式；生产缺模型时明确“AI 未配置”或按部署策略拒绝 AI 执行，不能静默伪装成功。补模型协议 fixtures、超时/取消、工具参数和结果、截断、上下文/费用/时间预算；真实网关验证只使用获准数据。若采用 DeepSeek thinking，需要在所选端点上核实协议字段往返，不沿用未经验证的兼容假设。

Hermes 仍是本地 TS 实现。早期 `Prompt/2026-09-06-chatagent-inception.md` 记录过“框架思路而非具体 SDK”的澄清，因此当前不把集成上游 Hermes 当成独立聊天的阻塞项。若继续要求实际复用上游，以独立 ADR、固定版本和受限执行适配 PoC 决策，不能凭包名宣称已经集成，也不应为此重写现有权限边界。

### PLAN-01：后续任务仍混有已完成和不再必要的内容

`docs/tasks.md` 的旧后续方向仍列“接平台凭据”“补审批中心”“将 simulated 升级交付”，而后面的实际代码已具备审批中心和原生投递；ADR 中的部分“非目标/后续”也已被新功能超越。

本轮更新 tasks 的后续方向，历史阶段保留原样。后续技能和 Prompt 必须先看本报告及当前源代码，不能只加载 9 月 13 日旧问题表。主流聊天平台接入不再是主线或验收依赖。

## 建议阶段顺序

### Gate 7：可靠的原生消息闭环（下一次只做这一阶段）

目标：完全没有第三方聊天服务，两个普通成员与一个 AI 账号仍能可靠通信；服务异常退出和网络重连不会造成已确认消息丢失、重复或越权回放。

交付：事务存储设计与最小迁移、发送业务幂等键、原生入箱/回执/事件的一致性、SSE 游标补发/快照同步，以及隔离测试目录中的故障注入测试。

验收：
1. 外部通道关闭、无任何平台凭据，原生私聊/群聊/AI 投递均可运行。
2. 同一个发送请求重试只产生一条消息；有意再次发送使用新的业务键。
3. 在成功确认后强制终止测试子进程并重启，消息/回执/会话索引一致；提交前故障不声称成功。
4. 断线期间收到消息、撤回和群成员变更，重连后与服务端状态一致；重复补发不重复渲染。
5. 退群或被撤权的用户不能使用旧游标读消息、附件或审批；游标过期有明确恢复路径。
6. JSON 历史迁移有备份/校验/回滚；现有 199 用例继续通过，并新增以上专用测试。

不要同阶段同时实现上游 Hermes、定时任务、SSO、语音、OCR、多个数据库或第三方平台。

### Gate 8：可恢复的 AI 工作闭环

建立步骤检查点与审批续跑；验收“上传 Excel → 汇总并生成 Word → 审批 → 原生发给同事”，中断/重启/再次批准不重新生成或重复发送。保留产物来源、版本、授权和审计。

### Gate 9：真实 Agent 与适度主动性

先完成一个获准模型端点的真实工具闭环，再逐项增加事件触发、定时任务、截止时间提醒、待办跟进和个人授权偏好。每项自动化有负责人、触发条件、权限、预算、暂停/撤销及人工接管。不是通过不断群发“主动消息”实现自主性。

### Gate 10：企业内网试点

补安装引导、成员邀请/设备管理、备份恢复、TLS/部署检查、升级回滚、真实多用户测试和明确容量目标。生产登录、开发模式、模型数据出网政策必须可见；独立聊天不等于模型也必然完全离线。

## 给后续开发者的最小指令

“以本报告为现状基线，实施 Gate 7：原生消息的持久提交、业务幂等和 SSE 断线补发。保留已完成的成员/群聊/审批功能，不接第三方聊天工具、不使用真实生产数据做故障测试。先写复现和验收，再实施最小事务边界；完成后报告新增测试与迁移策略。暂不扩展真实 Hermes 或定时任务。”
