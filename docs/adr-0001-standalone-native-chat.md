# ADR-0001：ChatAgent 是独立产品，不依赖第三方社交/办公软件

日期：2026-09-13 · 状态：已采纳（用户方向决策）

## 背景

早期简报把「第三方 IM 联系人」当作主要入口（QQ/企业微信/钉钉/飞书），Web 只作为管理台，`docs/research.md` 也以 webhook 适配器为主要交付。这与产品目标「内网聊天中的 AI 工作主体」存在张力：如果成员身份、会话、消息、文件都依赖外部聊天或办公软件，ChatAgent 就无法独立提供可信身份、对象授权、任务终态与交付回执。

用户明确要求：**项目应该是独立的，脱离其他社交聊天办公软件。**

## 决策

1. **原生优先**：ChatAgent 自带身份（成员目录 + 会话登录）、会话、消息、文件、任务、审批与回执；产品在没有任何第三方平台凭据时功能完整可用。
2. **第三方 IM 是可选适配器**：钉钉/飞书/企业微信/QQ 的 webhook 网关保留为插件，默认关闭（`CHATAGENT_ENABLE_EXTERNAL_CHANNELS=false`）。未显式启用时，`/api/webhooks/:channel` 返回 404，核心路径不依赖它们。
3. **客户端形态**：Web 工作台即原生聊天客户端（登录 → 联系人 → 会话 → 消息 → AI 任务/审批卡片）；Electron 桌面壳继续作为同一客户端的桌面入口。
4. **AI 账号是原生联系人**：AI 以 `agent` 类型出现在联系人列表，与成员共享同一套会话与消息模型。
5. **不改动已验收的安全语义**：对象授权、任务终态、产物归属、审批/outbox 规则对原生通道同样生效；原生投递在进程内完成，不经过 outbox（outbox 只约束对外副作用）。

## 影响

| 领域 | 变化 |
| --- | --- |
| 身份 | 新增成员令牌 → 会话令牌登录（`/api/auth/login`），会话令牌与 HttpOnly Cookie 双通道（EventSource 不能带自定义头） |
| 会话 | `Conversation` 增加 `origin`（native/external）、`targetKind`（agent/member）、`targetId`；`accountId` 变为可选 |
| 消息 | 原生发送 `/api/conversations/:id/messages`：AI 会话触发任务，成员会话直接进入对方收件箱 |
| 实时 | 新增 `/api/events/stream`（SSE），按订阅者逐条重新授权后推送消息/任务/审批事件 |
| 目录 | 新增 `/api/contacts`，返回同组织成员 + AI 账号 |
| 前端 | 新增登录页与原生聊天视图，聊天成为默认入口；原「会话」测试台视图移除 |

## 非目标

- 不接入真实 QQ/企业微信/钉钉/飞书凭据（保留适配器，作为后续可选工作）。
- 不做群聊、已读回执、在线状态、消息撤回、音视频。
- 不改变 Gate 1/2/4 已确立的授权、终态、审批与回执规则。

## 后续

- AI 的 `send_message`/`forward_file` 目前仍走网关（无真实通道时 `simulated`）；下一步应提供 **原生投递通道**，让 AI 主动消息直接进入成员收件箱并返回 `delivered`。
- 群聊、成员资料、消息检索、附件预览；成员自助注册仍需管理员签发（安全默认）。
