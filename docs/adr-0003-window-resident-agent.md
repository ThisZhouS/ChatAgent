# ADR-0003：后台运行绑定客户端关窗常驻

日期：2026-09-15。状态：已采纳，用户明确决策。

## 决策

后台运行与客户端常驻绑定：Electron 主进程管理 LocalAgentHost 和 Hermes 执行进程。关闭窗口不退出应用，继续后台任务；用户明确退出应用，则停止后台任务、清理本应用启动的执行进程并退出。

不再要求 Host 脱离 Electron 主进程存活，不引入独立守护进程、Windows Service、额外后台关闭工具或隐式自启动。Host 类可保留模块化接口，但不据此扩大部署形态。

本决策覆盖 ADR-0002、旧 Gate7A Prompt 和审查路线中与其冲突的“Electron 主进程退出后继续运行”“独立 Host 入口”“后续必须服务化”等要求；原始文档保留历史，实施时以此为准。

## 交互与生命周期

| 动作/情况 | 目标行为 |
| --- | --- |
| 员工正常使用 | 聊天与受限 Agent 任务并行 |
| 点击窗口关闭 | 关闭或隐藏窗口，托盘保留，Host 与任务继续 |
| 从托盘或再次启动打开 | 恢复界面，复用现有单实例，不新增调度器 |
| 暂停后台 | 停止领取新任务；运行中任务显示真实状态，取消为单独操作 |
| 托盘“退出 ChatAgent（停止后台任务）” | 停止派发、取消活动执行、有界等待、保存状态、清理自有进程树，再退出；有任务时给出明确提示 |
| 主进程崩溃/被强制结束 | 不承诺继续工作；下次启动将未知执行标为中断或按安全策略恢复，不误报成功、不重复副作用 |
| 无人操作但应用常驻 | 已授权任务可以继续，需审批动作仍等待 |
| 关机/注销/休眠 | 不承诺持续执行，不自动安装服务或防休眠；恢复策略另行验收 |

不再设计“退出整个客户端但后台偷偷继续”的路径。窗口关闭与应用退出通过文案、托盘和首次提示清楚区分。托盘初始化失败时应提供可发现的恢复/退出入口，避免关闭窗口后留下用户无法管理的后台进程。

## 保留的要求

- 独立于第三方聊天软件；组织服务不可达时仍应有本地 Agent 工作台。
- 真实 Hermes 集成、安全工具范围、可信授权、文件保护和预算。
- H-01 重复执行、H-02 审批伪造、H-03 吞落盘错误、H-04 取消被覆盖、H-06 IPC 契约仍需修复。
- H-05 保留为实例/存储约束：优先单 Electron 实例与单 writer 防护，不新增多进程租约系统作为发布前提；未来若扩展共享存储必须重新设计互斥。

## 验收

关窗后任务继续、重新打开任务可见；明确退出后本应用执行器停止且没有遗留子进程；取消终态不被迟到结果覆盖；重启不重复已完成任务；异常退出不误报成功。测试仅处理本应用创建的测试进程，不能按进程名称批量杀其他 Python/Hermes 进程。

## 实施状态

现有“Host 在 Electron 主进程 + 托盘常驻”方向符合本次决策，不再算架构缺陷。停止清理、状态可靠性与本地工作台仍需按当前代码补测。本次只更新需求与路线，不修改程序或宣称新增验收通过。
